## 2. 设计原则与尺寸

面向 ESP32-S3-Touch-LCD-3.49 的 640×172 横屏。硬件屏幕短而宽，主内容始终是一层胶囊，不沿用桌面第二、第三态的向下展开。

屏幕顶部是高度约 30px 的设备与连接状态行，中部胶囊从 y=34 到 y=132，高度 98px；底部 y=139 到 y=166 显示提醒或辅助信息。两侧保留 16px 安全距离。

只有本机时胶囊宽 608px；有远程时为 **498px 大胶囊 + 12px 间隔 + 98px 小圆**，总宽仍为 608px。聚焦本机时大胶囊在左，聚焦远程时大胶囊在右。本机身份始终在左、远程身份始终在右，交换的是宽度，不交换设备身份。

大胶囊内有最多三个 46px 圆圈，圈间距 6px。LOGO 为 36px，状态环为 3px，中间有 2px 白色内边距。选中项用底部小点和柔和光晕识别，不出现方框。触摸目标使用整个 46×46 区域。胶囊内容文字区也可以整体点击。

任务标题 20px；时间 16px 加粗；摘要 14px；状态与顶部辅助信息 11–12px。原生固件的 CJK 字体现在以 16px 为主，落地时需要生成或引入 12/14/20px 对应字形，不能把当前单一字体直接拉伸后声称效果相同。真机审核时如果 12px 不足够清晰，可提高为 14px并减少辅助文字。

采用浅灰蓝背景、白色胶囊、深色标题。蓝色表示执行，琥珀色表示需要用户关注，绿色表示成功，红色表示失败，灰色表示停止或连接不可用。状态还同时使用文字和符号，避免仅依赖颜色。

## 3. 十二种基础组合

1. **01 本机、无任务、无提醒**：显示产品 LOGO、Bright Moon、当前时间及“暂时没有任务，留一点时间给自己”。未来一小时无提醒。点击文字切换更安静的空闲详情。
2. **02 本机、无任务、有提醒**：保留产品 LOGO和空闲状态，底行显示最近提醒时间、标题及其余数量。点击底行查看提醒内容。
3. **03 本机、单任务、无提醒**：一个 Agent 圆圈，当前任务标题、活动、计时。
4. **04 本机、单任务、有提醒**：任务保持完整，提醒独占底部一行。
5. **05 本机、多任务、无提醒**：最多三个任务圆圈，选中圆圈右侧显示对应内容，时间跟随焦点。
6. **06 本机、多任务、有提醒**：三个任务入口加独立提醒行，提醒不占 Agent 圆圈名额。
7. **07 有协同、两端无任务、无提醒**：本机大胶囊保留产品 LOGO，远程小圆显示设备图标、设备名称和“空闲”。即使无任务也不能把在线设备隐藏。
8. **08 有协同、无任务、有提醒**：两端设备状态完整可见，本机提醒留在底行。
9. **09 有协同、单任务、无提醒**：本机大胶囊一个任务入口；远程小圆显示远程任务数量。
10. **10 有协同、单任务、有提醒**：在 09 基础上添加独立提醒行。
11. **11 有协同、多任务、无提醒**：本机三个任务，远程两个任务；点设备小圆交换焦点，换到远程后只显示远程任务圆圈。
12. **12 有协同、多任务、有提醒**：完整组合；本机任务、远程状态和提醒都可达，计时归属明确。

这里“有提醒”基础场景指未来一小时内即将提醒的任务。已经到点的提醒另见场景 20，使用“现在提醒”，不会继续显示旧的倒计时。远程任务与本机提醒同时出现时，提醒详情明确标记“本机提醒”。将来远程提醒必须带来源设备标识，不能混入本机待办而丢失来源。

## 4. 任务选择与设备切换

### 4.1 任务选择

点击具体 Agent 圆圈，选择该 task_key，并立即显示该任务的活动/摘要与时间。任务标题、计时、环色和进度必须来自同一个 task_key。再次点击同一个任务保持选中；点击文字区域才切换概览/详情，避免只想选任务却意外退出详情。

同一设备最多三个任务圆圈同时可见。超过三个任务时，胶囊使用“两个实际任务圆圈 + 一个 … 圆圈”，总计仍为三个圆形入口。当前选中任务一定出现在两个实际圆圈中；… 上的小角标 +N 表示未直接显示的任务数量。点击 … 打开固定 640×172 内的任务选择页，每页三个任务卡片，显示标题、状态和时间。点击卡片选中任务并返回；待审核任务直接进入审核阅读页。选择第五个后仍显示该任务圆圈、一个其他任务及 …，底部明确显示 5 / 5。

后续实现采用稳定 task_key，不用当前原型的 fixture 数组位置作为线上身份。手动焦点按设备分别保存；数据刷新不重置焦点、不重播入场动画。任务退出时选同组最近存活的任务，无任务时回到该设备空闲。列表在用户触摸期间不重新排序，避免触点下的任务突然变化。

### 4.2 设备切换

点击小圆后，大胶囊从 498px 收到 98px，另一个从 98px 展开到 498px，时长约 460ms、缓出；间距保持 12px。设备 ID 不改变，互换的是焦点与内容宽度。没有上下展开，也没有两个独立区域叠盖。

固件实现动画时使用同一个插值值 u，同时更新两颗胶囊的宽度及右侧胶囊的 x 坐标。任意帧满足 `local_width + 12 + remote_width = 608`。中段降低正文透明度，宽度稳定后再显示正文，以免文字被压成一团。触摸过程只响应一次切换，后续点击采用最后一次目标；断线提示可以中止动画并落在确定布局。低动态模式直接切换。

当前原型覆盖两台设备。超过两台时，设计建议在小圆标记“工作站 · +1”，长按小圆 600ms打开覆盖中部胶囊的横向设备选择页；选择后回到固定一长一圆布局。在线列表需要独立设备数据支撑。这项选择页没有混入本次已完成的两设备原型，也不声称已经实现。

### 4.3 提醒

底部显示最近提醒，额外提醒只显示数量。到点时使用琥珀色文字“现在提醒”，不闪整屏、不自动打断用户正在查看的任务。点击提醒进入固定高度内容卡，再点文字返回此前设备和任务。没有 Agent 时仍保留产品 LOGO 的首页，提醒详情才使用 LOGO_EXE。

提醒详情底部固定为“← 返回 / 5分钟后提醒 / 已知晓”。返回仅关闭页面；5分钟后提醒将本轮设为snoozed并由电脑按300秒重新调度；已知晓只结束本轮，不删除周期任务。尚未进入有效提醒期的未来预告只读，两个操作按钮禁用。操作发送后等待真实电脑回执，成功才退出本轮；过期、版本变化和重复提交由原有TaskStore拒绝或幂等处理。

## 5. 异常、完成与授权

- **待授权**：Agent LOGO 保留，环为琥珀色，显示“待授权”。远程需要授权时小圆也显示“待授权”；用户主动切换查看，不因连续到达的请求来回抢焦点。新设计支持设备端同意和拒绝：阅读完整请求、决定、二次确认、等待来源回执。本次已新增SOLO2完整请求与操作通道，仍保留SOLO1旧版只读兼容。HTML是模拟数据，固件通过桌面真实接口操作。
- **完成**：圆圈变绿色，中心为居中的勾，摘要显示结果、时间冻结；展示期限沿用桌面退场规则。
- **失败**：红环和感叹号，摘要给出简短原因，完整日志留在电脑端。
- **人为停止**：灰色状态环与原 Agent LOGO继续显示，“已停止”，不会出现空白圆圈。
- **远程失联**：本机正常运行，小圆显示离线；点击后显示自动重连文案。绑定信息仍保留，不把离线等同于绑定失败。
- **USB 失联**：整屏连接状态明确标记断开，已有数据标记最后同步时间，计时和执行动画停止。重连等待新 epoch / revision 的有效状态后才恢复。
- **进度不可量化**：显示“实时活动 · 无可量化计划”。仅来源明确提供计划与完成数时画步骤链和 2 / 4 等计数。不能用事件数推测任务完成百分比。

## 6. 与现有代码核对：落地前必须补的数据

已阅读 `monitor/esp32/compact.py`、`Product/Firmware/ESP32-S3-Island/island_model.h` 与 `island_ui.cpp`。现有协议具有全局最多 5 项 tasks、任务 device_id、状态、摘要、计时、计划、主题、idle 最近提醒和全局 focus，可复用现有 USB 服务与生命周期。

但当前**通过任务推导设备**，不能可靠表达“在线但没有任务的远程电脑”。此外提醒字段只有截短标题、时间和数量，无法支撑本预览中的完整提醒摘要。不能只改绘制代码就认为所有设计场景已经可用。

建议新增兼容能力字段，先协商新能力，再发送扩展数据：

```json
{
  "capabilities": ["device_inventory", "reminder_preview", "focus_per_device"],
  "devices": [
    {"id":"local","name":"本机","connection":"online","task_count":3},
    {"id":"peer-stable-id","name":"工作站","connection":"online","task_count":2}
  ],
  "reminders": [
    {"id":"opaque-id","device_id":"local","title":"产品评审",
     "summary":"准备演示文件和本周项目进展","due_at_ms":0,"state":"upcoming"}
  ],
  "reminder_total":2
}
```

示例 `due_at_ms:0` 仅占位；正式帧必须是真实绝对时间，不能照抄为有效提醒。tasks 仍通过 device_id 关联设备。总数来自桌面准确聚合；当实际任务多于当前同步上限 5 时，必须分别给出总数与已同步数量，ESP32明确显示“已同步 n / 总计 m”，不能显示不存在的详情。

维持已存在的 8000 字节帧上限：设备清单有界，例如最多 4 台；首个提醒摘要有界，其余提醒只发统计，UTF-8按字节安全截断；若超限优先缩短摘要，并明确截断标记。正文隐私关闭时仅显示状态，不发送预览中使用的业务标题与正文。

当前十二基础组合内最多 5 个 Agent 任务；提醒行是单独投影，避免它占用 Agent 圆圈。未来如需传更多任务，需独立修订分页协议和帧预算，不直接增大固定数组后无限发包。空闲协同设备也需继续发送心跳与连接状态，不靠任务残留来维持显示。

## 7. 固件实施边界

审核后可改 `island_ui.cpp` 的固定控件布局和状态绑定，保留现有 QSPI、触摸、共享 LVGL 锁、USB唯一读写线程、PWR长按3秒及电源弹层。圆圈、标签和胶囊对象启动时一次性创建；更新时只写变化字段。字体和LOGO生成独立资源，不从SD卡动态解码每一帧。

桌面补设备与提醒投影，固件补有界解码及型号字段；保存每设备焦点，状态绑定独立于布局动画。默认只对聚焦的执行/授权任务呼吸；完成、停止、断线不播放执行动画。动画每帧只更新小区域，性能和功耗需要在真机测量；浏览器流畅不代表已达到ESP32帧率。

主题本次先审核浅色基线。未来跟随桌面颜色时，文字与环色要做对比度保护；ESP32是实体屏幕，所谓透明度应合成成实际颜色，不能留下透明黑边。

## 9. 本轮修订：更多入口与设备端反向审核

### 9.1 更多入口不能藏住审核

当任务数为 1–3 时直接显示对应圆圈；超过 3 时显示两个任务圆圈与第三个 … 圆圈。用户选择的任务始终可见，列表刷新不能让正在点击的圆圈换成另一项。未直接显示的任务含待审核请求时，… 使用琥珀色环和 ! 角标，进入全部任务页后各待审核卡片同样高亮。远程设备未聚焦时，小设备圆显示“待审核”；点击切换设备后再选择具体请求。

不能用单纯的全局 attention 布尔值推断哪个任务需要审核。必须有稳定的设备 ID、任务 ID、请求 ID 和审核队列。一个任务有多个审核请求时，线上实现先显示“有 N 项待审核”，按创建时间列出；每次只决定一条，不能默认同意全部。本轮实现每任务当前首个请求；后续请求由来源刷新依次发布，不批量授权。

### 9.2 640×172 内的审核界面

审核页临时占据屏幕内容区，不向屏幕下方展开。顶部一直显示“本机审核”或“工作站 · 远程审核”；返回后恢复原先胶囊、设备与任务焦点。

1. 操作与任务：来源、Agent、任务、操作目的。
2. 完整参数：命令、工作目录、目标文件或网络地址、申请权限。
3. 影响说明：写入、删除、网络、安装脚本等来源实际声明的信息。不能自行断言任意命令无副作用。
4. 决定页：同意本次、拒绝；不提供默认永久同意。
5. 二次确认：再次显示任务及具体操作，提交只绑定该请求。
6. 等待回执：按钮禁用，显示“已发送，等待来源设备确认”。
7. 结果页：来源确认后才显示已同意/已拒绝。超时显示“结果暂未确认”，查询原请求状态，不能重新生成请求盲目重发。已过期或另一端已处理则禁用旧决定。

原型为了审查固定为四页短请求；正式实现必须按完整内容动态分页，不限死四页。完整载荷未加载完、缺失、被截断、哈希校验失败时，不能启用同意。可以返回任务或转到已支持的电脑/手机审核渠道。读取全部页面是辅助交互，不是安全保证。权限相关描述来自同一不可变请求版本；请求变化应明确提示并重新阅读。

### 9.3 双向通信设计，不绕过 Agent 本身的授权机制

目标链路：

```text
ESP32 请求详情 / 提交决定
        ↓ 同一条 USB 串口（版本与能力协商）
本机 SOLO：设备身份、请求版本、动作有效期与幂等核验
        ├─ 本机任务 → 对应 Agent provider 审核接口
        └─ 远程任务 → 既有可信协同连接 → 来源 SOLO → Agent provider
                                                        ↓
ESP32 ← 关联请求结果与最新任务状态 ← 来源端实际处理回执
```

旧SOLO1的actions与CMD保持只读兼容。新实现通过control句柄与SOLO2分页/决定/回执更新桌面路由、固件解码及串口队列，复用来源provider的真实审核能力。只提供日志观察、没有审批接口的 Agent 应显示“该来源不支持设备审核”，不能伪造审批成功。

建议新增能力 `approval_details_v2`、`approval_decision_v2`，保留旧固件只读兼容。界面概览只携带 opaque request_id、origin_device_id、task_key、request_revision、expiry、可用动作；点击后按页请求同一版本的完整内容，给出页数、总字节数、内容哈希与完整性标记。每帧仍遵守 8000 字节上限，使用有界分块和过期释放机制。稳定设备身份与会话 epoch 分离，远端重启后请求必须重新确认有效，不能靠设备显示名路由。

提交包括 command_id、request_id、request_revision、origin_device_id、task_key、choice、与该USB会话绑定的短期动作令牌。令牌在可信桌面端签发和验证，不能在板上自行构造授权。桌面根据受控映射选择 provider，不执行板子传来的任意 shell 字符串。拒绝仅拒绝当前请求，不直接把整个任务改成取消。

来源端原子核对 pending 状态及版本，执行一次并记录 command_id 结果；相同 command_id 查询/重试只能返回相同结果，不重复执行。ACK只是传输确认，RESULT必须来自授权路由实际返回；来源仅“接受处理中”时仍维持pending。手机或电脑同时处理同一请求时，先完成的有效决定生效，后到者收到 already_resolved，不覆盖。断线后先查询原请求状态，过期令牌不得重放。

USB设备首次启用控制由用户在SOLO设备设置明确开启；远程动作继承既有绑定关系和操作能力，被删除的绑定立即停止路由。底层帧不是加密串口协议，不把CRC或哈希当作加密；需要无线接入时应使用统一设备服务的认证与加密链路。审计只记录必要来源、请求、决定及结果，不额外落盘敏感命令参数。

### 9.4 新增预览与验收

- 场景 23：本机第五项待审核，… 圆圈高亮，进入后选择该项完成拒绝演示。
- 场景 24：远程五任务，隐藏审核高亮，进入后选择该项完成同意演示。
- 场景 25：提交后模拟超时，只允许查询原状态，无盲目重发。
- 场景 26：请求过期或已被其他端处理，显示不可覆盖的结果。
- 原型所有回执均为本地 fixture，不调用真实 Agent，不产生真实授权。

正式实施另测：跨设备同名任务、请求版本变化、连续点击、串口掉线/重连、远端重启、其他端并发审批、超时后迟到回执、多请求排队、超长参数分块、隐私关闭、provider不支持审批、绑定撤销和重放。所有回执必须匹配来源/请求/command_id，不能误更新当前刚切换到的其他任务。


## 10. 待办操作与本次实施定稿

提醒详情采用固定屏幕页：上方来源和时间、中部标题及正文、底部三个44px高的按钮。待办不使用“同意/拒绝”术语。多个有效提醒可通过列表切换；正文过长可滚动阅读。未来提醒预告不能提前执行本轮操作。任务圆圈与提醒独立显示，提醒不挤占Agent圆圈。

电脑端使用现有TaskStore.act的occurrence_id、cycle及幂等command_id；设备端不自行改周期、创建待办或删除任务。远程待办通过原有已绑定PeerService路由到来源TaskStore，不能写入本地同名任务。

本轮实施保留全局5个Agent任务上限和独立最多5个有效提醒，并明确上限；独立设备清单保证无任务协同仍可见。超过上限不伪造可达的任务详情。审核详情按页传输，每页按实际16px中文字形的显示预算分行，完整文档有界；参数不完整、隐藏或不受支持时不开放同意。桌面仅在用户启用ESP32控制且非仅状态隐私模式时发布控制能力。

USB升级采用独立SOLO2 GET/DETAIL、DO/RESULT、QUERY消息，继续使用SOLO1 STATE/ACK显示握手供老设备只读兼容。新固件声明支持SOLO2才开启控制。所有长时间Agent操作放在已有owner执行器，串口线程不能阻塞等待。操作token短期绑定具体不可变请求，command_id用于持久化幂等；重连清空阅读进度，未完成的操作只查询结果。

来源adapter目前通用返回可能只表示已提交，因此诚实显示“已提交来源，等待实际状态确认”，不把accepted当作succeeded。待办的SQLite事务提交成功可报告succeeded。不能证明执行效果的授权结果不显示“工具已执行成功”。

最终测试包括HTML原型、Python串口模拟与真实存储、LVGL实际代码主机渲染及交互断言、ESP32目标完整编译；真机烧录、电池、触摸手感和帧率另由实机验收，不自动烧录。
