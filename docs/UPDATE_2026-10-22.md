# SOLO 源码更新与审查：2026-10-22

本次相对于 GitHub `main` 的 `82931f8`（局域网手机查看更新）整理独立 SOLO 的新增源码。重点是 Claude Code 监控，同时包含本地已经实现、尚未上传的多电脑协同与配套界面。发布范围是源码、测试、设计文档、必要静态资源；没有重新构建安装包。

## 1. Claude Code：从未接入到真实事件监控

新增 `monitor/claude_monitor/`，包括事件投影、SQLite 邮箱、Hook 助手、安装器、进程状态识别、独立详情面板和来源设置。

- 支持 Claude Desktop 的 **Code 标签页本机会话**及 Claude Code CLI，普通 Chat / Cowork、WSL、SSH 和云执行不计为已支持。
- 根据真实 Hook 显示请求开始、读取检索、修改文件、命令/验证、子 Agent、压缩、待授权、响应结束、失败等阶段。Hook 未报告的指标不凭空估算。
- 第二态展示当前阶段与观察到的链路；第三态展示工具结果、子 Agent、压缩次数、模型与目录等。真实 TodoWrite 成功事件可提供计划；完成摘要单独显示。
- 授权桥默认关闭。开启后仅处理当前任务、当前请求和版本对应的“同意一次 / 拒绝”；超时、关闭、重复提交和过期请求不能产生误批准。
- 长度受限、被脱敏或不能完整展示的授权参数留在 Claude 原界面处理；不改变 Claude 的永久权限策略。
- 多轮追问、迟到事件、子 Agent 和 Stop 后继续执行分别处理，避免轮次混合。重启从邮箱水位开始，不重播旧完成任务。
- 安装 / 修复 / 检查 / 卸载入口位于来源设置。只识别 `--monitor-solo-claude-v1`，保留用户其他 Hook 与权限配置，并备份原设置。
- `run.py --claude-hook` 进入轻量 Hook 模式，不启动桌面窗口、托盘或第二个监控进程。图标从 `monitor/icon_asset/claude_logo.png` 加载。

共享改动包括 `app.py` 设置路由、`source_config.py` 配置校验、`source_hub.py` 来源注册、`detail_panels.py` 面板分派、手机投影以及设备协同来源白名单。具体说明见 [Claude README](../monitor/claude_monitor/README.md)。

## 2. 多电脑协同与独立远程布局

新增 `monitor/multi_diverse/`：设备身份、配对、持久化、TLS/WSS 通信、协议投影、动作回执、来源控制与专用 UI。

- 双方确认校验码和共享权限，按来源分别授予状态、详情和操作能力；默认不开启远程审批、问答与停止。
- 远端请求须匹配来源、任务轮次、请求版本和有效能力；执行队列中再次核对权限。命令回执区分已发送、成功、拒绝与结果未知。
- 同一任务 ID 在不同设备不会互相覆盖；拒绝来源混淆、重放和过期命令。断线、停止刷新、终态与重启历史都有独立处理。
- 有远程任务时，顶部保持“一长一圆”，总宽度与下方详情一致，间距为 12px；展开详情保持原尺寸。没有远程任务时使用原本的本地岛。
- 来源任务仍在来源电脑执行，关闭另一台电脑不会迁移或接管执行。当前不是公网中继、NAT 穿透或任意云同步。
- 手机不自动转发另一台电脑的任务；现有手机服务仍是只读 HTTP，不能将电脑 WSS 的加密能力误认为手机服务已升级为 HTTPS。

实现与限制详见 [多电脑协同说明](../monitor/multi_diverse/IMPLEMENTATION.md)。

## 3. 手机在线状态与通信修正

修改 `monitor/phone/server.py`、`service.py` 与网页 `transport.js`，使用服务端 challenge 和浏览器前台回执判断当前连接，支持 SSE 与轮询回退。页面退到后台或连接中断后，不会仅因服务端仍发心跳就永久显示手机在线。

本地胶囊时间后可显示手机连接图标；手机投影增加 Claude 已观察阶段和详情，继续禁止把敏感原始数据或可写权限直接暴露到只读手机端。

## 4. 提醒时区、幂等与启动恢复

- 提醒定义增加 IANA 时区，SQLite 模式升级到 v3。已有数据库迁移前备份，模式与版本更新在事务中完成。
- 每周提醒按定义的时区计算；间隔提醒保持实际时间间隔语义。夏令时不存在的时间不触发，重复时间避免重复提醒。
- 设备协同中的提醒操作增加命令回执，同一命令重复到达不重复忽略或确认，不同内容复用同一命令 ID 会被拒绝。
- 修复首次启动 `source_states` 缺失导致的崩溃：初始快照包含空来源状态，设置面板对缺失/异常值提供连接中或异常提示。
- 缺少 `tzlocal` 时，待办显示明确错误，Agent 监控继续运行；恢复依赖后可以继续读取。不会为绕过错误而偷偷用 UTC 调度。
- `requirements.txt` 补齐 `cryptography`、`tzdata` 和 `tzlocal`，不绑定开发者的 Conda 环境。

## 5. 设计与资源

- `monitor/multi_diverse/UI/` 包含真实远程布局实现、可交互设计页、模型测试及合成示例渲染图。
- `Product/APP_design/` 包含三端一致的页面规划和 HTML/CSS/JS 原型。这是设计产物，不宣称手机 App 或原型里的全部双向能力已经交付。
- 复制必要的 Claude、手机和设备图标。个人 `data/` 下的壁纸、角色上传、任务、配对身份和运行历史不上传。

## 6. 审查重点与交付边界

已逐项核对来源注册、配置持久化、命令分流、详情面板和主程序入口；Claude 等外部来源命令不进入其他 Agent 的控制逻辑。Hook 等待发生在独立子进程，来源轮询线程不等待人工审批。

发布前扫描拟提交文本中的常见密钥格式、私钥头、个人账户与机器路径，并审查 Git 暂存清单。此检查不等于完整安全审计。测试中的虚构路径和模拟凭据保留，用来验证隐私过滤。

旧 `MonitorSolo-0.1.0-windows-x64.zip` 与 `SHA256SUMS.txt` 保持不变。当前新功能需要运行源码；冻结 Hook 的新安装包、干净 Windows 安装及真实 Claude Desktop 版本兼容性，需另行验收。

## 7. 发布验证

在准备上传的独立仓库副本中运行 Python 全套、Claude 专项、Python 3.10 启动恢复测试与 Node 测试；测试目录与配置均为临时数据，不使用真实 Claude 账号、模型 API 或个人配对资料。最终结果记录在 [源码发布检查记录](SOURCE_REVIEW.md) 的 2026-10-22 章节。

## English summary

This source update adds local Claude Code monitoring and optional one-time approvals, bidirectional desktop collaboration with a separate remote-island layout, foreground-aware phone presence, timezone-aware reminders, and startup error recovery. Ordinary Claude Chat/Cowork and remote execution environments are not covered. UI prototypes remain design artifacts. No installer was rebuilt: the existing 0.1.0 ZIP and checksums are unchanged. Personal data, credentials, runtime databases, caches and build environments are excluded.
