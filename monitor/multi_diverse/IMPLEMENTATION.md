# SOLO 多电脑协同：源码运行与验收说明

更新：2026-10-24。范围仅为 `monitor_solo`；本次没有打包或修改 BrightMoon 主干；源码同步至 BrightMoon_V3 的 1021test 分支。电脑协同现采用“绑定即协同”，手机设备服务的独立权限设置保持原样。

## 1. 如何测试

在两台 Windows 电脑上运行本次源码。已有安装包仍是旧版，本次没有改动 `dist/` 或生成新安装包。

```powershell
# 在工程根目录，使用你运行 SOLO 的 Python 环境：
python -m pip install -r monitor_solo/requirements.txt
python monitor_solo/run.py
```

本机用于自动化验证的解释器为 `monitor_solo/.build-venv/Scripts/python.exe`，其中已安装此次新增依赖 `cryptography`、`tzdata`、`tzlocal`。不需要额外安装浏览器引擎；手机和设备 SVG 用 Pillow 在本机按 DPI 绘制。没有更新旧版离线安装材料，也没有自动修改另一台电脑的环境。

1. 两台电脑连接互通的可信私人局域网，在「远程连接 → 电脑协同」分别刷新、选择网卡并保存开启。默认电脑服务端口 18766；原手机服务默认 18765，两者独立。
2. A 点击「生成邀请 → 复制当前邀请」，通过可信渠道交给 B；B 点击「绑定电脑」并粘贴。邀请 5 分钟有效；发起绑定后，A 有 2 分钟确认。已有唯一网卡时界面默认选中，点击邀请或绑定可自动开启协同。
3. 两边核对相同校验码，A 点击「确认绑定」。B 粘贴邀请已经表达加入意图，不再要求第二次确认或逐项选择权限。绑定后双向共享全部本机来源的任务状态、详情，以及来源实际支持的提醒处理、授权、问答和停止操作。每次 Agent 授权仍需用户点击，不是自动同意。
4. 在 A 启用既有 Codex、OpenCode 或 Harness 适配器，并启动一个测试任务。B 应出现远程圆圈，点击切换来源，再点击长胶囊展开；B 无需安装 A 的 Agent。
5. 测试双向：在 B 创建另一个任务，A 应收到 B 的状态。两边使用相同会话 ID 也不会覆盖对方。
6. 无需管理共享权限或暂停状态。开启协同时自动显示绑定电脑的任务；「关闭协同」停止本机服务但保留绑定；「删除绑定」立即撤销本机互信并清理该设备缓存和凭据。仅同一 Wi-Fi 名称不保证网络互通，访客隔离/防火墙可能仍阻断连接。

两端应更新至本次源码。服务启用状态和绑定持久保存，重启后恢复；启动时没有网络、短暂断网或监听地址改变，服务每 5 秒重试。已绑定设备约每 5～6 秒重连；网卡变更每 10 秒检查。双方通过已认证连接交换新地址，并保留原 TLS 指纹。如果两边保存的地址都失效且无法建立任一方向连接，可点「更新地址」填写对方当前协同地址，无需删除绑定。没有实现局域网自动发现、公网中继或 NAT 穿透；本次不自动修改防火墙。

## 2. 实际界面

- 只有本机任务：继续使用原有连体灵动岛和本机多任务布局。
- 有远程内容：本地固定左侧、远程固定右侧；一个长胶囊、一个圆圈，总宽 420px，组成 348 + 10 + 62。
- 展开后顶部形状保持不变，下方独立卡片间隔 12px。切换来源不切换展开层级；点击当前长胶囊收回第一态。
- 远程详情最前面显示设备符号及名称。多设备/多任务选择在卡片内部完成，不再另外弹一个任务切换窗口。

## 3. 数据和线程边界

`app.read_snapshot()` 先形成**仅本机**事实，交给 PeerService 发布，再与收到的远程事实合并供桌面显示。接收数据不会再次发布给其他电脑，不会进入本机 Agent 的执行循环，不会创建远端提醒的本机定时器。

网络服务、加密身份、SQLite 操作由独立 asyncio 工作线程持有；Tk 只读取复制出的状态。远端操作经过有界队列交给 owner；本机提醒在 Tk 线程事务处理，Agent 命令在单独工作线程调用既有适配器，不阻塞绘图。

新增代码主要位于：

- `identity.py`：永久设备 ID、自签名 TLS 证书、DPAPI 密钥保存。
- `service.py`：邀请/确认、双向 WSS、重连、健康、权限、命令队列和回执。
- `store.py`：订阅水位、当前视图、有限日志、权限版本、命令幂等收据。
- `protocol.py`：有限白名单字段、来源/代际身份、隐私处理、请求校验。
- `owner_controls.py`：只在 owner 上解析已有 Harness 交互桥接能力，绝不把桥接钥匙发到局域网。
- `panel.py`、`UI/island.py`、`UI/geometry.py`：原生远程详情、独立外壳、来源高度兼容。
- `UI/icons.py`、`UI/motion.py`、`UI/settings.py`：现有图标、减少动画偏好、电脑协同页。
- `phone/presence.py` 及手机 transport：前台页面收包证明；不增加手机 Agent 控制接口。

整合点包括 `monitor/app.py`、`monitor/settings.py`、`src/source_hub.py`、`UI/settings_panel.py`、`UI/task_strip.py`、`tasks/store.py`、`tasks/schedule.py` 和任务编辑页的时区提示。新增依赖写入 SOLO 的 `requirements.txt`。

## 4. 保存什么、不会保存什么

在当前 SOLO 数据根目录下，电脑互信保存在 `multi_diverse/identity.dpapi` 和 `multi_diverse/peers.sqlite3`。永久密钥和设备互信凭据使用当前 Windows 用户 DPAPI 加密；不要把别人的数据目录复制过来当作新电脑身份。TLS 装载所需临时 PEM 仅在装载期间存在，随后删除。

- 设备绑定、地址、凭据、设备身份和订阅序号持久保存。旧记录第一次启动时迁移为完整协同并解除旧暂停，不轮换设备密钥；迁移只执行一次。来源过滤与权限校验仍留在底层协议中，设置页不再要求用户配置。
- 当前远端正文和有限投影尾部是本机数据，应按个人数据管理；它们不是可公开提交的源码。
- 历史退场继续使用原来的 DisplayHistory；网络心跳、标题变化、重启不会擦掉收据。
- `tasks.sqlite3` 升级到 schema 3，保存 IANA 时区；旧数据库在该迁移前生成 `.pre-v3.bak`。已知晓实例不重新提醒；每周规则跳过夏令时不存在的时间，重复时间使用第一次。
- 提醒已知晓/延后和对应命令收据在同一事务中提交。Agent 外部副作用不能与本地数据库组成原子事务，超时/断线显示“结果待核对”，不自动重放。
- 测试目录、DPAPI 文件、数据库和迁移备份已加入或保留忽略规则，不作为源码上传。

## 5. 权限和连接状态

最多绑定 5 台其他电脑，手机的最多 3 个设备记录独立管理。电脑绑定表示信任对方查看本机监控内容并提交来源支持的操作。不会将对方内容转发给第三台电脑或手机。没有来源实时能力时不出现可执行的审批按钮。删除绑定后新操作被拒绝，已发送给 Agent 的操作不能承诺撤回。

所有电脑连接固定校验邀请里的 TLS 指纹，并验证双方与永久身份绑定的凭据。拒绝浏览器 Origin、错误 Host、非所选子网、非法载荷及超限请求。错误证书不会自动接受。

owner 发放短期、不可猜测的能力凭据；以 owner 的 monotonic 时间判断期限，不依赖客户电脑时钟。操作还需要完整目标代际、请求版本、实时权限、当前来源能力；进入本机执行队列后再次检查。后续状态证明完成前，“已发送”不被解释成“Agent 已执行成功”。

WSS 在线不代表来源工作正常：来源采样超过 5 秒未刷新时停用操作；15 秒无有效网络活动判离线，计时冻结。离线/暂停按既有 60 秒退场规则处理；终态按用户的保留时间处理。首次全量中的历史终态只作为基线，不弹出、不响铃。

手机在线证明由服务端 challenge 和浏览器前台 receipt 构成，绑定会话与 viewer、15 秒内有效且一次性消费；最多 2 个 viewer/会话、合计 6 个，按会话计数。SSE 与轮询/304 都能确认。关闭或切到后台后不会因为服务端仍在发送心跳而一直显示手机在线。

## 6. 与完整设计的明确边界

本轮采用**有界完整快照替换**，不是逐事件增量协议：最多 200 个实体、正文 180 KiB、整条消息 256 KiB；超限按提醒/待处理请求优先，并显示遗漏计数。每份快照原子应用，断线重连重新取完整快照。同序号内容不一致、旧序号、终态倒退和权限版本倒退拒绝。日志只保留最多 33 份/24 小时，不宣称保存 7 天全部执行事件。

默认仅 owner 发声。当前未开放远端额外声音、远程修改提醒定义、接收端手机再展示第三方内容；这些是设计里的可选扩展，不在设置页假装可用。来源关机后，不接管它的任务执行或定时提醒。手机继续使用原有只读 HTTP 查看服务，电脑协同的 WSS 加密不等于手机 HTTP 已升级为 HTTPS。

## 8. 真机验收清单

这些项目不能由一台电脑上的回环测试代替：

1. 两台电脑同 Wi-Fi 双向配对，退出并重开后自动连接；阻断一个连接方向，确认另一方发起连接仍可工作。
2. 两台同时执行任务、相同会话名、超过 5 个推荐任务；来源切换不改变阶段，详情属于当前长胶囊。
3. A 真实发起一次低风险授权；B 同意/拒绝；A 原应用收到一次操作，双方状态一致。删除绑定后，旧按钮不能继续执行。
4. A 创建测试提醒；B 已知晓/忽略；确认 A 的持久实例状态、下一周期及重启后的行为。
5. 暂停来源、关闭来源、拔网、休眠恢复；先冻结计时并禁用控制，再退场，旧记录不反复弹出。
6. 手机上前台、切后台、关页、恢复和轮询降级；图标不会把长期保存的离线手机当成在线。
7. 100% / 150% / 200% DPI、深浅纯色和壁纸、透明度、来源切换、授权文本滚动与问答输入；检查卡片间隙和背景一致。

## 2026-10-24 简化绑定与恢复机制

### 原有问题

旧版双端各自选择权限，默认只有状态没有详情；暂停与隐藏选项会持久化，导致“已连接却看不全”。网卡变化会退出服务，连接失败被吞掉，用户只能看到离线，难以定位。以上为代码确认的问题，不等同于已确认某台用户电脑的具体故障原因。

### 当前行为与边界

- 邀请方确认一次，受邀方自动等待绑定结果；没有逐项权限弹窗。
- 旧绑定迁移保持 token 与设备指纹，清理旧投影并增加策略版本。
- 网卡恢复重建监听；手动关闭会中止自动恢复。
- 更新地址仅改变位置，不改变设备身份。指纹不符会拒绝连接。
- 旧版仍可连接，但旧版一侧的权限与暂停需升级后才能迁移；不要只更新一端。
- 数据目录的 DPAPI 凭据属于原 Windows 用户。部署另一台电脑时只复制源码或安装程序，不复制个人 data 目录。
- “在线自动协同”要求两端进程在运行、开启协同、网络互通。电脑睡眠、程序彻底退出、防火墙阻断都不是权限按钮能够解决的问题。
- 没有待监控任务时，可以显示设备在线，但不会凭空生成灵动岛任务；已完成任务仍遵循用户设置的保留时间。

### 验收重点

真实 TLS 回环测试覆盖单侧确认、默认详情和审批能力、重启后保留绑定、端点修复、离线删除后拒绝重连、错误指纹拒绝，以及启动无网络和网络恢复。测试仅使用隔离目录与模拟 Agent；两台物理电脑的防火墙和 Wi-Fi 仍需实际验收。

## 2026-10-24：协同灵动岛展开异常与重复绘制修复

用户报告 `ImageDraw.rounded_rectangle` 的 `y1 must be greater than or equal to y0`：展开状态先置为 true，但弹簧首帧高度仍为约 62px，下方卡片起点却是 74px，形成倒置矩形。现在仅在实际帧超过卡片起点时绘制卡片，并按可见高度限制圆角。保留顶部 62px 和 12px 间隔。

## 2026-10-24：协同断线过渡与设置页统一视觉

### 现象与原因

- 第一态每 55ms 呼吸灯刷新时，旧实现先同步独立悬挂窗口，再清空并绘制胶囊画布；Windows 分层窗口的重绘顺序可能让用户看到一帧空白胶囊。协同外壳还会在父轮询完成后再次筛选并绘制，使旧布局和新布局连续出现。
- 另一台电脑重启、网卡短暂变化或服务线程异常时，旧 worker 的 `finally` 清空远程目录。接收端下一次读取只看到本地任务，于是胶囊收起；用户误以为持久绑定失效。
- 协同页顶部使用原生 ttk 按钮，按钮有独立的系统底色，和设置弹窗的壁纸/透明主题不一致。

### 修复方式

- `monitor/UI/island.py` 将挂件同步移到完整胶囊绘制之后；隐藏状态仍先同步隐藏挂件。`multi_diverse/UI/island.py` 缓存协同基础背景帧，呼吸灯只更新光晕与环形指示器。
- `PeerService` 将设备身份、指纹、绑定凭据和远端目录分开管理。临时 worker 异常时保留最后目录并标记 `connection_error`/“来源失联 · 自动重连”，不清空状态；重新运行只重建网络会话，成功认证后以新的流代次接收快照。显式关闭或删除绑定仍立即清空并停止重连。
- `_connection_error` 对 401（身份/数据目录不匹配）、409/503（对端重启或已有连接）、网络超时分别给出可操作提示；自动重试不重新配对。连接成功后清除过渡错误并刷新远端任务。
- `multi_diverse/UI/surface.py` 与 `RemoteSettings` 使用同一壁纸裁剪、自绘圆角卡片和分段页签；避免系统弹窗和不透明按钮覆盖背景。绑定确认、地址更新和删除均在页面内完成。

### 运行边界

绑定成功后不需要再次授权；双方进程保持运行且网络可达时自动监控。若对端彻底退出或电脑睡眠，界面会保留离线过渡状态并按既有退场时间隐藏任务；对端恢复后自动重新订阅。删除绑定才会撤销信任。
