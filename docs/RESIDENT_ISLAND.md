# 灵动岛常驻与空闲状态

## 使用方式

在控制面板「监控」页顶部打开「灵动岛常驻」。默认关闭，选择立即保存在 Solo 的 `settings.json` 中，重启恢复。这个开关只决定没有可见任务时是否保留窗口；不打开 Agent 来源、不启用已关闭的任务提醒，也不延长任何任务的保留时间。退出 Solo 仍然关闭全部窗口。

任务列表/网格的切换按钮只显示对应图标，不再画背景色块。鼠标点击区域和键盘焦点保留。

## 空闲时的三个形态

第一态为 360×62 逻辑像素的胶囊：左侧使用 `MonitorSolo_logo.png`，外围绿色指示灯和同色光晕有呼吸变化；中间以 24px Georgia 粗斜体居中显示「Bright Moon」；右侧按未来 1 小时的提醒预告显示状态：没有提醒时为绿色「无任务！」，有提醒时显示「N项任务」：数字深红色，文字深蓝色，无背景框。文字用 2 秒从右向左滑入，完整显示后停留 1 秒，用 2 秒滑出，间隔 0.3 秒后循环。移动速度为原先的 40%。滚动图层有独立裁剪区，不覆盖品牌文字或壁纸；浅色背景使用较深的绿色提高可读性。常驻空闲也支持原有悬挂卡通与位置设置。

第二态为 420×266：顶部保留胶囊栏，正文以「忙完了，给自己一点空闲。」开头。未来 1 小时内有提醒时显示「未来 1 小时 · 最近一条」、任务标题、真正开始提醒的日期时间及最多两行核心内容。这里的时间是预定时间减去提前量；若用户忽略过，则显示「再次提醒」及延后后的时间。长文本按可用宽度截断；窗口内多于一项任务时，右侧显示「另有 N 项」，不展开其余任务详情。

未来 1 小时没有提醒时显示「未来 1 小时暂无提醒」「安心享受这一刻。」「想起什么，再去『任务』记下来。」。任务提醒开关关闭时明确显示「任务提醒已关闭」；数据读取失败时显示「暂时无法读取提醒计划」，不会把错误伪装成没有计划。

第三态为 420×354：继续保留第二态内容，下方左侧显示任务的重复规则，或「把琐事交给提醒，把此刻留给自己。」；右下角显示用户在「个性化 → 空闲角色」选择的透明图像，素材来自 `data/cartoon/`，不再显示底部 Logo。开关和选择自动保存，支持扫描目录、预览和上传自定义图像。未来 1 小时没有提醒时，第二态即可在右下角显示该角色；有提醒预告时第三态再显示。精灵高度按第三态与第二态的高度差减 8px 计算，即 354−266−8＝80 逻辑像素，按屏幕 DPI 缩放，保持原比例和透明背景；右侧留 26px、底部留 10px，文案为图像留出空间。图像宽度上限 120px，极宽图等比缩小以避开文案；图片在选择或刷新时读取、按 DPI 缓存，缺失图片时保留文案，不影响监控。点击顶部或展开卡片中的正文、空白、角色图像，均可按胶囊→第二态→第三态→胶囊切换，空闲页面不会提供任何 Agent 授权、停止或知晓按钮。

## 任务退场和切换

- 运行中、待授权的真实任务沿用原监控 UI，常驻空闲不占五任务名额，不生成假的任务 ID、审批、完成音或显示历史。
- Agent 完成后先保留用户设定的时间。到期后从可见任务中移除，历史去重继续生效。暂停、失联、取消等仍沿用其已有独立退场规则。
- 还有其他可见任务时继续显示它们；最后一个可见任务退场时，自动从当前形态收回第一态，显示空闲品牌胶囊，不关闭窗口。
- 空闲状态转换只执行一次。用户再次展开查看下一条提醒后，400ms 的后续轮询不会反复收回卡片，也不会重置跑马灯计时。
- 新 Agent 执行或待办提醒到来时，恢复真实任务胶囊和原有详情、授权与声音行为。完成记录的晚到摘要不会把已退场任务重新弹出。
- 关闭常驻时：没有可见任务立即隐藏；有任务时继续正常显示，到期后隐藏。常驻与「任务提醒」开关彼此独立。

来源后台继续观察新执行与有效的新授权；「退场」仅意味着不再占用当前显示，不会停止 Agent 或断开整个来源。

## 实现边界

- `monitor/settings.py`：布尔配置 `island_resident`，默认 false，老配置自动补默认值，无数据库结构变更。
- `monitor/app.py`：保存开关后立即刷新；快照携带下一条提醒及任务数据可用状态。
- `monitor/UI/resident.py`：空闲三态、提示文案、绿色文字滚动图层及其 1 秒停留时序；字号随 DPI 调整，字形缓存避免每帧读字体。Windows 优先使用系统微软雅黑；缺少中文字体文件的其他系统退回可读的 Tk 静态文字。
- `monitor/UI/island.py`：窗口显示与真实任务退场分离，仅在进入空闲时自动收回；复用现有弹簧、壁纸、透明度、光晕与挂件生命周期。
- `monitor/tasks/store.py::upcoming_reminders`：只读查询未来 1 小时将开始提醒的任务；最近一条详情与总数量使用同一次查询，不创建实例、不领取声音。按提醒开始时间排序，排除暂停、已知晓、已过期实例，同时考虑延后实例和其独立的后续重复周期。
- `monitor/tasks/service.py`：只在常驻和任务提醒都启用时查询下一条，错误时清除旧预告。
- `monitor/UI/settings_panel.py`：监控顶部开关，来源及保留时间布局调整；`UI/tasks/page.py` 移除视图按钮底色。

以上全部在 `monitor_solo/` 内。没有修改 BrightMoon 主项目，没有新增第三方依赖，没有改动 Agent 协议或授权流程。

## 未来一小时任务预告（2026-10-17）

空闲跑马灯和第二态使用同一份数据，以实际开始提醒时间为准，统计范围为 `(当前时间, 当前时间＋3600秒]`，包含恰好一小时边界。预定时间在一小时以外、但提前提醒落在范围内的任务，也计入。已开始提醒的任务转入原待办监控卡片，不重复计入预告。

一个任务定义只统计一次：延后提醒和下一轮重复都落入窗口时，采用最早一轮；暂停、已知晓、过期、删除的轮次不重新展示，下一轮有效重复照常计算。查询不创建提醒实例、不领取或播放提示音。

顶部显示总数，例如「2项任务」；第二态显示最近一项的标题、开始提醒时间和内容，另显示「另有 1 项」。超过一小时的任务不再提前占据第二态；无符合条件的提醒时显示「未来 1 小时暂无提醒」，开启空闲角色后可在右下角显示角色。任务提醒关闭时顶部显示「提醒关闭」，读取异常时显示「读取失败」，不会伪装成无任务。计数变化会更新跑马灯文字，后续相同快照不会反复重启动画。

验证：47 项测试通过、0 跳过、0 失败。覆盖一小时边界、跨午夜、提醒提前量、关闭/删除、延后与下一轮去重、已知晓不重放、到时交给真实提醒卡片、异常清空、顶部/详情同步、1000 项文字适配以及既有空闲角色和待办测试。报告 `.artifacts/hour-preview.xml`；预览 `preview/solo-hour-preview-capsule.png`、`preview/solo-resident-next-reminder.png` 和 `preview/solo-hour-preview-marquee.gif`。只修改 Solo。

## 展开区域点击修复（2026-10-17）

第二态和第三态的正文、空白及角色图像，现在均可点击切换形态，不再限制于顶部胶囊区域。复用既有状态机：普通任务和空闲状态依次第二态→第三态→胶囊；已完成任务保持点击展开卡片直接收回胶囊，待授权任务保留原有阶段规则。

原有授权、停止、已知晓、忽略、任务切换、步骤折叠等控件优先处理，禁用控件的区域不会穿透触发收起；授权参数文本框继续支持阅读、选择与滚动。正文拖动不切换形态也不移动窗口，顶部拖动仍可移动窗口。新增正文命中区域不增加键盘 Tab 焦点，也不绘制大面积焦点边框。
