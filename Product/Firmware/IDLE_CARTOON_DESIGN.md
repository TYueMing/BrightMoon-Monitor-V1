# ESP32 空闲卡通：素材同步与界面升级方案

日期：2026-10-30。状态：设计稿，未实施上传和显示功能。本文图片为尺寸约束下的方案示意，不是真机截图。

## 1. 目标与结论

桌面「远程连接 → ESP32」可以选择透明卡通、同步到板卡，并控制是否显示。没有任何有效任务或当前提醒时，角色出现在当前长胶囊右侧；有任务立即让出空间。不改变 640×172 屏幕、608×98 单机胶囊及多设备 498×98 + 12px + 98×98 的结构。

推荐采用「电脑转换素材 → USB 分块传输 → 板端 SD 缓存 → 内存渲染」。图片只在首次同步、内容改变或板端缓存缺失时上传，状态消息只携带图片 ID 和偏好，不能每秒重复传图片。关闭显示不删除素材，再打开直接使用缓存。

## 2. 已核对的现有实现

- `monitor/src/cartoon_assets.py` 已有 `CartoonCatalog`，支持 PNG/WebP 透明素材导入、校验和本地保存；可以复用，不需要另一套素材目录。
- `monitor/esp32/serial_service.py` 已有唯一串口工作线程；`serial_client.cpp` 已有 SOLO1 状态和 SOLO2 审核协议。素材传输必须复用连接，不能第二次打开串口。
- `config_portal.cpp` 中 SD 只用于读取配置和证书，读取后调用 `SD_MMC.end()`。媒体使用前必须统一管理挂载，不能直接往现有配置加载函数里追加文件上传。
- `lv_conf.h` 使用 16 位色并开启 `LV_COLOR_16_SWAP`；PNG 解码和文件系统适配当前关闭。LVGL 内存池只有 48KiB，不适合存放任意用户原图。
- `island_ui.cpp` 固定控件树已经支持本机/远程焦点切换。新增角色应放在长胶囊 content 内，只分配一个图像控件，不按每帧创建销毁。

## 3. 显示规则

显示条件全部成立：设备偏好开启、素材校验成功、连接状态新鲜、全局 Agent 任务数为 0、当前有效提醒数为 0、没有审核/提醒/设备选择/关机等弹层。

判定使用完整可监控目录的计数，不能只检查当前焦点或屏幕已显示的前五项。仍在保留期的完成/失败任务属于可见任务；退场后才恢复角色。暂停、待授权、等待输入仍算任务。隐藏在其他设备或「…」中的任务也阻止进入全局空闲角色态。

未来一小时的提醒预告不算当前提醒，角色可显示，底部继续展示提醒时间；到达提醒窗口后隐藏角色。已绑定但无任务的在线电脑不阻止显示，继续保留一长一圆布局。连接过期/失联时隐藏角色，显示真实断线状态，不能把未知数据当成空闲。桌面应发送经过完整目录计数及来源新鲜度判定的 `idle_eligible`，而不是要求板端凭截断列表猜测；来源读取失败或当前展示的远程来源失联时该值为 false。用户主动关闭的监控来源不参与计数。

任务进入：立即开始隐藏，最多 120ms；有紧急待授权直接隐藏，操作入口不等动效。任务全部退场：稳定空闲 500ms 后，在约 220ms 内渐入，避免状态短暂抖动导致闪烁。开关关闭立即隐藏。默认静态，不做持续跳动；可选 2px 缓慢起伏，开启减少动画偏好时停用。

## 4. ESP32 布局

单机长胶囊：左侧保留品牌 LOGO，中部显示 Bright Moon 与空闲短句，右侧独立容纳角色；时间放在角色左边。不把角色当成任务圈，不给角色绘制运行状态环。

- 单机尺寸保持 608×98，右边距 16px，角色槽最大 96×84，垂直居中。
- 多设备长胶囊保持 498×98，同样预留 96×84 的右侧区域，文字缩短为一行摘要；短设备圆保持 98×98，不放卡通。
- 图片先去掉透明空白，再等比例缩放 contain，完整保留人物，不拉伸、不裁头脚、不套背景方框。
- 角色槽右侧与胶囊边缘保留至少 16px；文字/时间和角色槽至少间隔 12px，不能靠透明像素碰巧错开。
- 点击角色沿用长胶囊点击语义，禁止形成挡住触摸的独立可点击层。焦点交换时角色随长胶囊整体隐藏/渐入，不能停留在旧设备圆上。
- 角色属于这块屏幕的装饰设置，不跟随远程电脑的个性化变化；焦点换到空闲远程设备时仍使用屏幕自身所选角色。

## 5. 桌面设置与交互

在现有 ESP32 连接卡片下增加「空闲角色」，不挪动审批权限开关，不要求用户为了显示装饰开启审批权限。

1. 独立开关「无任务时显示卡通」，默认关闭，按板卡持久化。
2. 当前图片预览、图片名称、板端状态：未同步/传输中/已同步/等待连接/存储不可用。
3. 「选择角色」复用当前 `data/cartoon/` 素材库；「导入图片」沿用透明 PNG/WebP 校验。提示用户使用抠图，优先在 640×172 实际尺寸预览里判断清晰度。
4. 选中即保存期望值，在线且素材不存在时自动排队同步；提供「重试同步」和传输中的「取消」。失败时保留上一个可用角色，不先清空屏幕。
5. 状态信息显示板卡 ID、容量/剩余空间与适配结果；只有固件声明支持媒体时才启用同步。旧固件明确显示「需要更新固件」，不做无效按钮。
6. 图片显示开关与桌面端空闲角色开关独立；同一图库可共用，不能互相覆盖选择。

## 6. 数据与持久化

桌面以固件报告的稳定 board_id（不使用 COM 号或可重复的显示名称）保存设备偏好。建议字段：`idle_cartoon.enabled`、`source_ref`、`asset_id`、`motion`、`revision`；同步状态另存，不混入用户偏好。`source_ref` 只允许本地素材库的相对引用，不向板端下发电脑绝对路径。

图片 ID = 转换后受控格式完整内容的 SHA-256；颜色布局、宽高、格式版本也纳入哈希。桌面保存期望 ID，板端分别报告已缓存 ID 与当前已应用 ID。选新图未上传完时不谎报已应用。

板端在 NVS 只记录开关、当前 ID、偏好版本和绑定的桌面身份；图片存在 `/solo-island/media/cartoon/<sha256>.bmimg`。NVS 只在配置变化时写，不随每秒状态写。固件升级保持格式版本可检测；不兼容时请求重新同步，不读取错误字节。

重连先交换能力、board_id、媒体清单和配置版本：同一板卡已有相同哈希时只更新开关，不重传。更换图片、清卡或校验失败才补传。未收到新鲜监控数据时即使有缓存，也不展示成正常空闲状态。

## 7. 图片格式与内存

电脑使用 Pillow 做透明边界裁切、等比例缩放、sRGB 归一化、元信息移除。禁止直接将几十 MB 原图交给单片机解码。

建议媒体 v1 明确规定 RGB565 小端颜色加 A8 透明度的逐像素三字节格式，另有魔数、版本、宽高、长度与哈希。实际显示推荐不超过 96×84：24,192 字节，约 23.6KiB；硬上限 128×128：49,152 字节，约 48KiB。固件验证宽高乘法及长度上限，再按当前 LVGL 的 TRUE_COLOR_ALPHA 内存格式和 `LV_COLOR_16_SWAP` 转换，不能把自定义文件直接当成 `lv_img_dsc_t`。

图像从 SD 一次读取到受控 PSRAM 缓冲，绘制不读卡。新图加载/校验成功才在 LVGL 锁内切换描述符，旧缓冲等渲染不再引用后释放；不得在 48KiB LVGL 池里同时放两幅图片。PSRAM 分配失败时保留旧图或隐藏角色，不重启、不阻塞监控。

首个实现只承诺静态透明图和位移动效，不承诺 GIF/WebP 动画。没有 SD 卡时可以明确提示不可持久保存，仍正常监控；如以后提供 RAM 临时模式，必须单独标明断电失效，不能假装已保存到设备。

64GB 卡的容量本身足够，但常见出厂 exFAT 不代表当前固件支持。需实测当前 ESP32 core/FatFs 配置，推荐经过验证的 FAT32 配置；挂载失败报告原因，不自动格式化用户卡。

## 8. 传输协议与调度

保留 SOLO1/2，新增能力协商后的媒体命名空间，例如 `SOLO3 CAPS / MEDIA_BEGIN / MEDIA_CHUNK / MEDIA_STATUS / MEDIA_COMMIT / MEDIA_ABORT / PREFS_SET`。帧必须带 request_id/upload_id，响应相关性不可只靠最后一个请求。文件传输与审批权限分开管理，SD 文件路径由固件根据哈希生成，不接受任意路径。

- CAPS 报告格式版本、最大尺寸/大小、支持的分块大小、SD 状态及空闲空间。
- BEGIN 携带资产哈希、长度、宽高和格式，返回已接收偏移；只保留一个受限上传会话。
- CHUNK 使用 1KiB 原始字节的 Base64 与 offset、CRC32；确认后发下一块。帧小于现有 9KiB 行缓冲，不能把整张图塞进 STATE。
- 重复块内容相同则幂等确认，错序/CRC 不符返回明确偏移。断线后查询临时文件和已确认长度再续传；断电后重新核验 `.part`，不盲信最后一次内存偏移。
- COMMIT 校验全部 SHA-256、格式与大小，写入并关闭不可变哈希文件后再更新选中引用。FAT 断电不能仅靠 rename 保证事务，重启需重新校验成品和引用；失败退回旧图。
- 设置确认与媒体传输确认是独立回执，桌面不能收到 CHUNK ACK 就显示「已应用」。

审批/待办操作与状态心跳优先，媒体分块低优先级。桌面复用唯一串口线程，板端解析后交给有界 SD 工作队列，SD I/O 和哈希不在 LVGL 锁内执行。暂停媒体不能暂停状态心跳；上传失败不取消 Agent 审核。拔卡、低空间、写失败、用户取消时清理当前会话但保留已生效素材。

115200 UART 的 8N1 理论上限约 11.5KB/s，Base64 再增加约 1/3 字节量；这不等于原生 USB CDC 实际速度。预计素材很小，但实际传输耗时、ACK 时延与审核响应必须测量后再作承诺。

## 9. 代码边界

桌面新增 `monitor/esp32/media_catalog.py`（转换及哈希缓存）、`media_transfer.py`（分块/恢复/重试）、`media_settings.py`（素材 UI）；扩展 `config.py`、`serial_service.py`、`compact.py`。复用 CartoonCatalog，串口继续由原线程持有。

固件新增 `media_store.*`（统一 SD 生命周期）、`media_protocol.*`（受限接收会话）、`idle_cartoon.*`（PSRAM 图像及可见性）；扩展 `serial_client.cpp`、`island_model.h`、`net_client.cpp`、`island_ui.cpp`，让 `config_portal.cpp` 改用统一 SD 服务。网络回退也须传递一致的显示偏好，旧网络帧缺字段时保持已保存偏好而不是重置；本方案的素材上传先使用 USB，Wi-Fi 文件上传不默认开放。

## 10. 验收要求

覆盖：单机空闲/多设备全部空闲、远程有任务但本机空闲、超过五个任务、完成保留期、待授权/待回答/暂停、未来提醒与到点提醒、断线与重连、弹窗与关机、亮/暗主题、超宽/超高/半透明/全透明素材、切换焦点、重复刷新不闪烁、板卡倒装后的点击。

传输覆盖：取消、随机断线、乱序/重复/损坏块、SHA 不符、拔卡、低空间、断电后恢复、板卡 ID 不同、旧固件、同图不重传、配置开关重启保持。上传同时执行审批、提醒确认和电源长按，测量状态新鲜度与响应时间，不能让媒体传输触发现有失联阈值。

验证边界：本轮仅检查现有源码并生成 UI 方案图；尚未实测 SD 格式、真实 USB 吞吐、媒体断电恢复、板端新图渲染。
